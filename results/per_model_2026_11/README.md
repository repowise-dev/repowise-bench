# Per-model agent loop, November 2026

The same coding agent answers the same questions about real code twice: once on its own, once
with Repowise. Five models, three held-out repositories, 24 questions, 576 sessions in 288 pairs.

## How it was run

- **Repositories:** thruwire/foreman (Python), okf-memory/okf-agent-memory (Go) and
  elstongun/leviathan (Rust), pinned commits, all created after every tested model's training
  cutoff. A zero-tool memory probe found 0 of 21 distinctive identifiers (`probe/memory/`).
- **Questions:** 24 (8 per repository: locate, flow, impact), written from the code before any
  run, each gold item checked at a cited line (`questions/`).
- **Agent:** Claude Code 2.1.288 headless (`claude -p`), model default effort, a fresh session
  per run, operator hooks, plugins and user settings off, read-only permissions.
- **Repowise:** the four core tools (`get_answer`, `get_context`, `search_codebase`,
  `get_symbol`), keyless index (`repowise init --yes --no-prose`), repowise at `061b2bc79`.
- **Grading:** deterministic regexes over the ANSWER section, no model judge. Correct means every
  gold item matched.
- **Statistics:** per-question means, paired difference, 95% bootstrap interval over questions
  (10,000 resamples).
- **Pre-registration:** [PREREG.md](PREREG.md), frozen before the grid, with amendments A1 to A6
  and the reason and time for each.

Transcripts are published as recorded, with three edits: local directory prefixes are replaced by
`BENCH`, `HOME`, `REPOWISE_SRC` and `REPOWISE_VENV`, the operator's user name by `user`, and three
fake credentials from a target repository's secret-scanner test fixtures by `FIXTURE_REDACTED`.
None of these touch a metric: `harness/render.py` on this directory reproduces `tables.md`
byte for byte.

## Reproduce

Check the published tables against the published runs (no model calls):

```
cd harness
python render.py > ../tables.md
```

Rerun a row against a given repowise commit (needs the three repositories cloned under `repos/`
and `bare/` at the pinned commits, Modal for the indexes, and a logged-in Claude Code):

```
RW_REPO=/path/to/repowise SHA=<commit> MODEL=claude-opus-5-5 REPS=3 bash harness/rerun_at_sha.sh
```

It indexes with that commit, runs one session at a time, halts on a usage limit and resumes where
it stopped, then prints the row (`harness/analyze.py`).
